## 1. 文字サイズ関連（重点）

### A. ◎ セクションのテキストを編集すると、外観設定が既定値に戻る（「字が小さい」の最有力原因）
- `SubtitleSection.cpp:13-26`（PostEditChangeProperty）と `SubtitleTrackEditor.cpp:142-148`（ダブルクリック編集）
- テキストを変えるたびに `bOverrideAppearance = true` が強制される。
- そのとき `AppearanceOverride` は未設定のまま（FontSize 24、FontAsset なし）なので、**トラック側で指定したフォントやサイズが無視され、24 に戻る**。
- 例: トラックで FontSize=48 → テキストを編集 → そのセクションだけ 24 で表示される。
- この後はトラック側の設定を変えても、そのセクションには反映されない。

### B. ○ ゲーム／PIE で DPI スケールが二重にかかっている
- `SubtitleSubsystem.cpp:59-63`（独自 SDPIScaler）と `:308-311`（GameViewport に追加）
- GameViewport のオーバーレイは、エンジン側（SGameLayerManager）の SDPIScaler の中にある。UMG の AddToViewport もこのスケールを使う。
- さらに独自の SDPIScaler で同じ値を掛けているため、実際の倍率は **S²** になる。

| 画面の短辺 | カーブ値 S | 現状 (S²) | UMG (S) |
|---|---|---|---|
| 600（PIE の小窓） | 0.56 | **0.31** | 0.56 |
| 720 | 0.67 | 0.44 | 0.67 |
| 1080 | 1.00 | 1.00 | 1.00 |
| 1440 | 1.33 | 1.78 | 1.33 |
| 2160 (4K) | 2.00 | **4.00** | 2.00 |

- 1080p だけは正しく見えるので気付きにくい。PIE では小さく、4K では大きくなりすぎる。
- ScreenPadding・ScreenOffset・ウィンドウ高さも同じように二乗で効いている。
- 確認方法: Widget Reflector で、字幕の上に SDPIScaler が 2 段重なっていれば確定。

### C. ○ エディタのプレビューでは、OS の表示倍率も掛かっている
- `GetSubtitleDPIScale()`（`:1762-`）は、物理ピクセルの大きさからカーブ値を出している。
- ところがエディタの Slate では、OS の表示倍率（例: 150%）がすでに掛かっている。
- そのため高 DPI モニタでは、エディタのプレビューがゲームより倍率分だけ大きく見える。
- エンジンの SGameLayerManager は、同じ計算のあとで親のスケールを割り戻している。同じ処理を入れるべき。
- 追加・削除・スケール計算で、毎回その時点の「アクティブなビューポート」を取得し直している（`:295, :332, :1539, :1771`）。
  - 追加した後に別のビューポートを選ぶと、スケールの基準がずれる。
  - その状態で削除すると、元のビューポートにウィジェットが残る。
  - タイマーのラムダは生の `this` を捕捉しているので、subsystem が破棄された後に落ちる可能性がある（→ 2-e）。

### D. ◎ 行の幅と高さを最初に 1 回だけ計測し、固定値にしている（リサイズに追従しない）
- `PreMeasureSlotText`（`:1453-1487`）と `InitTypewriterState`（`:661-691`）
- 倍率 1.0 で計測した幅と高さを、SBox の Width/HeightOverride に固定値として設定している。
- 実際の描画倍率ではグリフの丸め誤差が出るため、ウィンドウサイズによっては最長行が折り返される。行数が増えても高さは固定なので、文字がウィンドウからはみ出す。
- 画面幅より長い 1 行をタイプライターで表示すると、折り返しても高さは 1 行分のままになる。

### E. ◎ MessageWindowHeight が「固定の高さ」（既定値 120）
- `:1236-1242`
- フォントを大きくしたり行を増やしたりしても、背景のウィンドウは広がらず、文字がはみ出す（ShowMessage の既定 FontSize 50 で 2 行でもはみ出す）。
- A の「強制オーバーライド」は、この問題の回避策として入れたものと思われる。

### F. ○ FontAsset に FontFace を指定できるが、正しく描画されない可能性が高い
- `SubtitleSettings.h:106`、`SubtitleSubsystem.cpp:1162-1165, 1274-1277`
- `FSlateFontInfo(UObject*, Size)` が受け付けるのは UFont（IFontProviderInterface）が前提。UFontFace では、フォールバック用のフォントで描画される見込み。
- UMG でも、指定できるのは Font だけに制限されている。

### G. 参考: FontSize の単位（小さく見える原因ではない）
- このプラグインの FontSize は、Slate の内部値（96DPI 基準）をそのまま使っている。
- UMG はプロジェクト設定「Font Resolution」（既定 72DPI）で換算した値を表示する。そのため**同じ数値を入れると、このプラグインの方が約 4/3 倍大きく見える**。
- 小さく見える原因ではないが、UMG と数値を揃えたい場合は検討が必要。

## 2. その他の不具合・改善点

- a. ◎ JSON の Export/Import に、v1.3 で追加した項目（アウトライン、トレンブル、ウィンドウのスタイル・不透明度・角丸・画像、話者名の揃え、区切り線の詳細、ScreenOffset など）が入っておらず、往復させると失われる。
  - キーがない JSON を読むと `GetIntegerField` が 0 を返すため、**FontSize が 0 になる**。
  - 既存の `FJsonObjectConverter`（JsonUtilities には依存済み）を使えば、全項目を自動で扱える。
- b. ◎ CSV の Import が行単位で分割しているため、改行を含む字幕が壊れる（Export は改行をそのまま出力している）。
- c. ◎ トレンブルが有効だと、退場時のスライドアニメーションが上書きされて見えなくなる（`TickTremble` の `!bExitAnim` 条件）。
- d. ◎ 表示位置（上下・左右・ScreenPadding）がすべてのスロットで共通。位置の違う字幕を同時に出すと、最後に出したものの設定に全部揃ってしまう（仕様上の制限）。
- e. ◎ Slate タイマーのラムダが生の `this` を捕捉している（`:193, :789, :1564, :1691`）。また `Deinitialize` でトレンブルのタイマーを止めていない。
- f. ◎ 使われていないコード: `ToggleTypewriterOnAllSections` / `HasAnyTypewriterEnabled` / `BuildColorPresetMenu`
- g. ◎ `WrapTextByCharLimit` は TCHAR 単位で切るため、サロゲートペア（絵文字など）が分断される。禁則処理もない。
- i. △ 字幕のウィンドウ画像と区切り線の画像は、`LoadSynchronous` したテクスチャを FSlateBrush でしか参照していない。
  - GC に回収される可能性がある（特にパッケージ版）。Image Track のように UPROPERTY で保持するのが安全。未対応。
- h. △ アウトラインのレイヤー（最大 11 枚の STextBlock）は、それぞれ別に折り返しを計算している。アウトラインで計測幅が変わる場合、折り返し位置の付近で行がずれる可能性がある。

## 4. 決定事項（2026-09-30 回答）

- Q1 → (a) 強制オーバーライドを廃止し、ウィンドウは文字に合わせて広がるようにする。
  - 結果として、行数に合わせた MaxLinesPerPage の自動設定もなくなった。3 行以上のタイプライターは、トラックの MaxLinesPerPage（既定 2）でページ送りされる。
- Q2 → B を修正してよい（1080p 以外で表示サイズが変わるのは許容）。
- Q3 → FontSize の単位は今のまま（Slate の内部値）。ツールチップに単位と UMG との換算を明記する。
- Q4 → JSON のキー名が変わってもよい。旧形式の 3 つの bool キーは読み込めるようにしておく。
- Q5 → PIE では常に小さく見えていた。B（DPI の二重スケール）の症状と一致する。1〜4 の修正で直るなら、追加の調査は不要。

### 既知の注意点・次に確認すること
- **ビルドと実機での確認がまだ**（UE 5.5〜5.8 の各バージョン）。特に次の点。
  - PIE での文字サイズが UMG の TextBlock と同じ倍率になっているか（Widget Reflector で SDPIScaler の段数も確認）。
  - 高 DPI モニタで、エディタのプレビューと PIE の見た目のサイズが揃っているか。
  - タイプライターで、中央揃えの位置が最後まで動かないか。長い 1 行を入れたとき、折り返しとウィンドウの高さが合っているか。
  - JSON の往復（旧形式の JSON も読めるか）と、改行入りの字幕を含む CSV の往復。
- 以前のバージョンでテキストを編集したセクションは、Override Appearance が ON のまま既定値（FontSize 24）になっている。直すには、セクションの Override Appearance を OFF にする。
  - トラックの右クリック → Appearance → **Clear Section Appearance Overrides** で一括 OFF にできる（元に戻す可）。
  - 意図して上書きしていたセクションも OFF になる点に注意。
- 次のリリースで README の更新履歴を追記し、バージョンを上げる。MessageWindowHeight の意味（固定 → 最小）と、PIE での表示サイズの変化を明記すること。

## 6. 没案・将来の検討

- FontAsset と FontSize を UMG 標準の `FSlateFontInfo` に置き換える（書体の選択や字間の指定ができるようになる）。
  - 既存データの移行と、独自の 2 層アウトラインとの整合が重いため、今回は見送り。
- タイプライターを、未表示の文字を透明にしたリッチテキストで描く方式にする（文字位置がまったく動かない）。
  - アウトラインのレイヤーが多い今の構成では重いため、D の方式を優先する。
- FSubtitleAppearance の既定値（MessageWindowHeight=120、MaxLinesPerPage=2）を変える。
  - 既定値のまま保存されたアセットの見た目が変わるため、却下。
- A の直し方 (b)「強制は残し、最初にトラックの設定をコピーする」は、Q1 で (a) が選ばれたため没。
- FontFace から CompositeFont を組み立てて対応する案は見送り。
  - API の差分とフォントキャッシュの管理が重く、UMG と同じ「Font のみ」に揃えた。
